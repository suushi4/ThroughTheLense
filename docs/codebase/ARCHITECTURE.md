# Архитектура

## Архитектурный стиль

Многостраничный веб-интерфейс на HTML, CSS и ES-модулях. Дневник использует маршруты по фрагменту URL, а отдельные страницы имеют собственные модули. В браузере выполняются обработка материалов и воспроизведение сцены. Go-сервер раздаёт сборку, принимает HTTP-запросы и хранит готовые записи аккаунта. Гостевой архив работает через IndexedDB. [Маршруты](../../web/app.mjs) · [Сервер](../../backend/cmd/server/main.go) · [Гостевой архив](../../web/journal.mjs)

## Как данные проходят через систему

1. Редактор принимает рассказ, снимки и трек, проверяет материалы и пишет черновик в IndexedDB. [Редактор](../../web/app.mjs) · [Черновики](../../web/journal.mjs)
2. Из фото получаются миниатюра и оттенок рамки. Из рассказа предлагается дословная фраза. Анализ энергии трека даёт две отметки для фразы и возвращения кадра. [Сборка сцены](../../web/scene.mjs)
3. Плеер берёт текущую позицию аудио, определяет фазу сцены и меняет кадр, фразу и громкость фона. [Плеер](../../web/player.mjs) · [Звуки места](../../web/ambience.mjs)
4. Фасад дневника сохраняет день в IndexedDB гостя или через адаптер аккаунта. HTTP-режим записывает файл дня и строку с метаданными в SQLite. [Фасад](../../web/diary.mjs) · [HTTP-адаптер](../../web/account.mjs) · [Запись ревизий](../../backend/internal/httpapi/days.go)
5. Архив повторно открывает день. Версию можно экспортировать в JSON и ZIP. При публикации Go-сервер проверяет копию и отдаёт сцену по отзываемой публичной ссылке. [Формат](../../web/transfer.mjs) · [ZIP](../../web/day-folder.mjs) · [Публичная ссылка](../../backend/internal/httpapi/share.go)

## Ответственность модулей

| Модуль | Ответственность | Где лежит соседняя ответственность |
| --- | --- | --- |
| [`app.mjs`](../../web/app.mjs) | Экран редактора, архив, предпросмотр и действия над днём | Правила сцены в [`scene.mjs`](../../web/scene.mjs) |
| [`player.mjs`](../../web/player.mjs) | Воспроизведение готовой сцены и переход между фазами | Сохранение в [`diary.mjs`](../../web/diary.mjs) |
| [`diary.mjs`](../../web/diary.mjs) и адаптеры | Единый интерфейс архива и выбор хранилища | Вход и сессия в [`account.mjs`](../../web/account.mjs) |
| [`httpapi`](../../backend/internal/httpapi/) | Маршрутизация, доступ и проверка данных запроса | SQLite в [`store`](../../backend/internal/store/), файлы в [`copies`](../../backend/internal/copies/) |

## Повторно используемые решения

| Решение | Где применяется | Зачем |
| --- | --- | --- |
| Адаптеры с одинаковыми операциями | [`diary.mjs`](../../web/diary.mjs), [`cloud-diary.mjs`](../../web/cloud-diary.mjs) | Гостевой и авторизованный архивы используют один интерфейс |
| Клиентский плеер с функцией монтирования | [`gallery.mjs`](../../web/gallery.mjs), [`shared.mjs`](../../web/shared.mjs), [`home-lab.mjs`](../../web/home-lab.mjs) | Примеры, публичные ссылки и сравнение используют один механизм воспроизведения |
| Запись новой ревизии перед обновлением ссылки на неё | [`days.go`](../../backend/internal/httpapi/days.go), [`copies.go`](../../backend/internal/copies/copies.go) | Архив открывает полную копию |
| Периодическая уборка файлов | [`main.go`](../../backend/cmd/server/main.go) | Сервер убирает устаревшие файлы копий |

## Архитектурные риски

- Плеер и обработка медиа зависят от браузерных декодеров. Поддержка форматов ограничена в [`scene.mjs`](../../web/scene.mjs), а повторное открытие заново декодирует материалы в [`transfer.mjs`](../../web/transfer.mjs).
- Go-сервер хранит SQLite и файлы на одном томе. Конфигурация предполагает одну реплику. [Railway](../../railway.toml) · [Docker](../../Dockerfile)
