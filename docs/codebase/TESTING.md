# Проверки

## Стек и команды

JS использует `node:test` и `node:assert/strict`, Go — стандартный пакет `testing`. Сквозные сценарии используют Playwright 1.65.0 и Chromium. Для браузерных сценариев нужен запущенный локальный сервер с временным каталогом данных. Большинство сценариев принимают `TTL_TEST_URL`, базовый гостевой тест обращается к порту 8000. [Команды npm](../../package.json) · [Инструкция запуска](../../README.md#проверка)

```bash
npm test
(cd backend && go test ./...)
npm run build && node scripts/check-dist.mjs
TTL_TEST_URL=http://127.0.0.1:8080 npm run test:experience
TTL_TEST_URL=http://127.0.0.1:8080 npm run test:submission
(cd backend && go test -cover ./...)
```

## Расположение тестов

- Корневые `*.test.mjs` проверяют сцену и звуки. [Сцена](../../scene.test.mjs) · [Звуки](../../ambience.test.mjs)
- `tests/*.cjs` запускаются как самостоятельные программы Playwright. [Основные сценарии](../../tests/experience.cjs) · [Гостевой сценарий](../../tests/browser.cjs)
- `backend/internal/**/*_test.go` тестируют пакеты Go рядом с исходниками. [HTTP](../../backend/internal/httpapi/) · [Хранилище](../../backend/internal/store/).

## Изоляция и подмена зависимостей

Go-тесты создают временные файлы и поднимают тестовый HTTP-обработчик. Сценарий распознавания использует поддельный HTTP-сервер вместо Anthropic. Playwright открывает новые контексты, создаёт временные записи и подменяет отдельные ответы по URL. Сценарии с аккаунтом стоит прогонять над временной базой, поскольку они записывают в неё данные и могут упереться в лимиты регистрации. [Тесты аккаунта](../../backend/internal/httpapi/account_test.go) · [Подмена Anthropic](../../backend/internal/httpapi/ambience_test.go) · [Создание и проверка аккаунта](../../tests/experience.cjs)
