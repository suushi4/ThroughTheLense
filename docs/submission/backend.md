# Бэкенд: текст для описания решения

Сайт и API отдаёт один Go-сервер. Он развёрнут на Railway и пересобирается при каждом изменении `main` в GitHub. Перед выкладкой сборка проверяет, что в сайте нет битых ссылок и ошибок в коде.

Аккаунты устроены как обычный вход по почте и паролю. Пароли хешируются argon2id, сессия хранится в защищённой cookie. Каждый пользователь видит и меняет только свои дни.

День хранится целиком: текст, фото, трек и метки сцены лежат в одной копии формата `ThroughTheLense/day`. Её же можно скачать и открыть снова. Список дней находится в SQLite, копии — на постоянном томе. Сохранение атомарное: сначала копия полностью записывается на диск, и только потом запись в базе начинает на неё указывать, поэтому оборванное сохранение не повредит день.

Прежде чем показать день по публичной ссылке, сервер проверяет файлы по содержимому, а не по имени. Это настоящие JPEG, PNG или WebP и MP3 или WAV, трек длится 3–60 секунд, фраза дословно взята из текста. Ссылку автор создаёт и отзывает сам. По ней видна только эта сцена, без почты автора и остальных дней.
